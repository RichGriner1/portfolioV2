## 1. I gave agents a business to build

**Standalone A — day-one recap**

Build in public — day 1.

A side hustle with family used to mean months of nights and weekends. Now the agents do the legwork — read everything, file a brief with sources — so my hours go to judgment, not busywork.

Empty repo this morning. Working model + 100+ sources tonight.

---

**Standalone B — the reframe (research)**

The agents don't replace me on research. They take out the tedious part.

They go read everything and file a report with sources. I read it back, double-check what matters, and make the call.

Same judgment, a fraction of the hours. That's the superpower.

---

**Standalone C — the recursive bit**

The report my agents file every night is also the input for these posts.

Build in public, then let the build write the update. The loop reports on itself.

## 2. Constraints did more than motivation

**Standalone A — the rules**

Rules I gave the agents on day one:

Cite every claim. One pass, then stop. $3 a session. Nothing ships without me.

Constraints did more for the output than motivation ever has.

---

**Standalone B — one pass then stop**

The hardest rule to enforce on an AI: one pass, then stop.

Left alone it'll polish forever and call it progress. The constraint isn't about cost. It's about knowing when the work is done.

---

**Standalone C — the budget as a design tool**

I cap each AI work session at $3.

Not because I can't spend more — because a budget forces the agent to prioritize instead of chasing every thread at once. The limit is the feature.

## 3. The system reviews its own work

**Standalone A — the gate caught the lie**

Day one, my content pipeline's quality gate caught its first issue: a draft promised a guide that doesn't exist yet.

The AI wrote the post. A separate check caught the lie. Neither step trusts the other. That distrust is the design.

---

**Standalone B — separation of duties**

The AI that writes shouldn't be the AI that approves.

One drafts, a different one checks it against the rules, and I sign the last step. Same principle as code review — the author is the worst judge of their own work.

---

## 4. Better inputs beat better tools

**Standalone A — the screenshot hack**

My research sandbox blocks half the sites I need.

So I screenshot them myself, drop the images in an inbox folder, and the agents treat my captures as primary sources. Unblocked three dead-end research sections in an afternoon.

Sometimes the fix isn't a better tool. It's giving the tool better inputs.

## 5. I design systems an AI operates inside

**Standalone A — the through-line**

A design-system rulebook an AI reads. A content loop with quality gates. An agent that files a nightly report.

Different projects, same job: I design the system an AI operates inside. The AI moves fast; the system keeps it honest.

---

**Standalone B — the repo is the memory**

The AI doesn't remember yesterday. The repo does.

Every decision, every source, every rule lives in the files — so the agent that shows up tomorrow inherits everything the one from today learned. The memory isn't in the model. It's in the system around it.
