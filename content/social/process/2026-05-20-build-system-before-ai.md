# Build the design system before AI builds with it

> Schedule: **Wed 2026-05-20** · Pillar: process · Stance: builder · Status: draft

## LinkedIn

> After a lot of trial and error, I was excited to finally minimize the inconsistencies between design and development.
>
> But then I sat with the programmers and looked at the code. It was awful 😅. We had improved the experience and the speed of design.
>
> A good start. But not scalable.
>
> So I started working with the programmers on the proper structure of components and variables, on figuring out responsive design and how things map.
>
> Because of that, we're reaching more and more consistency. I'm excited about this new era of design engineering. I'm learning about code a lot more quickly than I did before, and I'm able to see the impact directly in how we're working and talking about products.
>
> As a design-system designer, my goal is for programmers to eyeball a page, see the right variables, and spend attention where it matters.
>
> Where I'd start:
>
> - **Audit your token layers.** Variables match Figma. Primitives feed responsive. Semantics name the role. Same names everywhere.
> - **Put it in design.md.** Tokens, design notes, and component structure in one file. Or a skill, if markdown isn't the right home.
> - **Stay explicit, every time.** Name the files, the structure, the conventions — even when the agent already has a skill. Long conversations drift.
