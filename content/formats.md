# Post formats

A library of reusable structures for posts. A format decides the **shape** of a post — never the voice (that's [voice.md](voice.md)) and never whether it's worth posting (that's the **substance bar** at the top of voice.md). Every format must still clear the substance bar.

A format is scaffolding, not a script. Use it when the material fits; don't force material into it. Formats are filed under the pillar they fit best, but most travel.

---

## Problem → Steps → Scale  ·  process

**Use when:** you solved a concrete, repeatable problem and the fix generalizes. Works as a Twitter thread or a LinkedIn post. **Not** for one-off observations — those stay single takeaway-first standalones.

**Shape:**

1. **Problem.** One or two lines. Name the specific pain concretely — the number, the actual symptom — so the reader recognizes their own situation. Open on the situation, not a hook-claim.
2. **Solution, in steps — max 5.** Each step is one beat: the move, not the theory. Bold the action, add a short why only if it needs one. Use **only as many steps as the fix actually has** — a 3-step fix is a 3-step post. Don't pad to five.
3. **How it scales.** The payoff, and *why it compounds* — across projects, people, or time. This is the "so what."

**Substance check:** the "How it scales" section *is* the takeaway. If you can't write it, the problem you picked doesn't generalize — pick a different one. A Problem → Steps post with no scale section is a tutorial, not a point.

**Voice watch-outs (from voice.md):**

- Steps are imperatives — bold rule, short reason. No throat-clearing.
- The three-item-list tell applies double here. Every step earns its place or it's cut.
- Problem opens on the situation: *"Onboarding a designer took two weeks."* — not *"Here's a productivity hack."*

**Worked example — Tool consolidation (Twitter thread):**

```
Onboarding a new designer used to take two weeks before they could ship. The cause was boring: eight tools, eight logins, no single source of truth.
```
```
Step 1: inventory what each tool actually did. Most of them overlapped. Half were habits, not needs.
```
```
Step 2: pick one home. A design-system site — components, tokens, and docs in one place, behind one link instead of eight bookmarks.
```
```
Step 3: move the source of truth there and delete the duplicates. If it isn't in the one home, it doesn't exist.
```
```
Step 4: point AI at that same home. Generated UI now reads the exact system humans do, so it comes back on-brand instead of generic.
```
```
How it scales: onboarding went from 14 days to 4 (Velvetum saw the same). Every new project starts from one source, not eight. Fewer homes, less drift — for people and for the AI reading them.
```

*(Four steps, not five — the fix had four. The scale tweet carries the takeaway.)*
